1. Información Básica de un Servidor

Fundamentos esenciales de red, hardware y software para desplegar un mundo multijugador estable.

🌐

Red y Puerto por Defecto

Minecraft Java Edition utiliza por defecto el puerto TCP 25565 (mientras que Bedrock emplea UDP 19132). Para permitir conexiones externas es indispensable abrir el puerto en el firewall del sistema operativo y en las reglas de red del proveedor.

TCP 25565 · server.properties
⚙️

Rendimiento y Tick Rate (TPS)

El motor del juego procesa la física, entidades y redstone a 20 ticks por segundo (TPS). Si el procesador se satura, los TPS caen por debajo de 20, provocando retraso en bloques y movimiento. El rendimiento depende principalmente de la velocidad por núcleo (Single-Thread).

20 TPS = 50ms por tick
💾

Gestión de Memoria RAM (JVM)

Asignar demasiada memoria sin optimizar el recolector de basura (Garbage Collector) provoca pausas bruscas. Se recomienda equilibrar los parámetros -Xms y -Xmx utilizando las banderas de Aikar con Java 21.

-Xms4G -Xmx4G -XX:+UseG1GC

2. Problemas Comunes y Soluciones

Haz clic sobre cada incidencia para desplegar el diagnóstico y los pasos de resolución.

Error "Connection timed out: getsockopt" al intentar entrar
RED / FIREWALL ▶
Causa: El cliente envía paquetes hacia la IP del servidor, pero un firewall (UFW, iptables, Windows Defender o el Security Group de la nube) está descartando las peticiones en el puerto 25565.
  1. Verifica que el servidor esté escuchando en todas las interfaces dejando server-ip= en blanco dentro de server.properties.
  2. Permite el tráfico TCP en el puerto 25565 dentro del firewall del servidor Linux:
sudo ufw allow 25565/tcp
sudo ufw reload
Caída severa de TPS y mensaje "Can't keep up! Is the server overloaded?"
RENDIMIENTO / CPU ▶
Causa: Generación simultánea de chunks nuevos cuando varios jugadores exploran rápido, o exceso de entidades acumuladas en granjas automáticas.
  1. Migra el núcleo de Vanilla a PaperMC para habilitar el guardado y carga asíncrona de chunks.
  2. Reduce la distancia de simulación en server.properties de 10 a 6 u 8 chunks.
  3. Pre-genera el mapa usando el plugin Chunky antes de abrir el servidor al público.
Cierre repentino del servidor por "java.lang.OutOfMemoryError: Java heap space"
MEMORIA JVM ▶
Causa: La máquina virtual de Java alcanzó el límite máximo de memoria asignada y no pudo liberar objetos en uso.
  1. Aumenta el parámetro -Xmx dejando al menos 1.5 GB libres para el sistema operativo (por ejemplo, en un VPS de 6 GB, asigna 4.5 GB a Minecraft).
  2. Ejecuta el servidor con parámetros optimizados de recolección de basura:
java -Xms4G -Xmx4G -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -jar server.jar nogui
Error "Failed to verify username!" al conectarse jugadores
AUTENTICACIÓN ▶
Causa: El servidor tiene activada la verificación contra los servidores de sesión de Mojang/Microsoft (online-mode=true) y el jugador intenta ingresar con una sesión inválida, sin conexión o desde un cliente no autenticado.
  1. Si todos los jugadores poseen cuenta oficial, basta con reiniciar el launcher para renovar el token de sesión de Microsoft.
  2. Si es una red privada o híbrida, ajusta online-mode en server.properties e instala un plugin de autenticación (como AuthMe) junto con SkinRestorer para proteger las cuentas.
